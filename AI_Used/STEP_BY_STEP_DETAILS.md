# Step-by-Step AI Contribution Details

Throughout the project, we integrated AI tools into specific stages of development to generate code and configurations. Below is a breakdown of where and how AI contributed at each stage.

### Stage 1: Architecture and Planning

**How AI Contributed:** We used AI to evaluate architectural options. It helped us confirm that building a custom Go webhook receiver using `client-go` was a viable, lightweight alternative to using the Kubebuilder framework for our operator.

### Stage 2: Probe Development and Containerization

**How AI Contributed:** AI generated the initial Python scripts (`dns_probe.py` and `connectivity_probe.py`) to expose custom metrics. It also provided the Dockerfile and Kubernetes `Deployment` manifests needed to containerize and run the probes natively inside the KIND cluster.

### Stage 3: Operator Webhook and Remediation Logic

**How AI Contributed:** The core self-healing logic was generated by AI. It wrote the Go HTTP server to intercept Alertmanager JSON payloads and implemented the `client-go` API calls required to restart pods (e.g., Calico/Flannel daemonsets) and modify network policies when an alert fired.

### Stage 4: Monitoring and Observability Setup

**How AI Contributed:** AI was used to generate the Prometheus configuration files. It provided the PromQL alerting rules for our `alerts.yaml` and generated the Grafana JSON dashboard ConfigMap used to visualize CoreDNS latency and pod connectivity success rates.

### Stage 5: Fault Injection and Testing

**How AI Contributed:** To test the system, we needed a way to reliably break cluster components. AI generated the specific `kubectl` bash commands for our `inject_faults.sh` script, allowing us to easily simulate DNS failures and CNI crashes to verify the operator's response.
